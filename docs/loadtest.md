# 并发压测报告（2026-11-03）

> 目的：给「并发」这件事一张可复现的曲线，而不是一句「支持高并发」。
> 脚本：`D:\tmp\legalrag_verify\loadtest.py`（起真服务 → 上传文档 → 多并发打点 → 抓 `/metrics` 算成本）

---

## 1. 环境与方法

| 项 | 值 |
|---|---|
| 机器 | Windows / AMD64，CPU-only（无 GPU） |
| 服务 | uvicorn 单进程，`backend.main:app` |

- **gateway** = I/O 密集型（等后端返回）

## 2. 修复前：`async def` 里跑同步阻塞代码

接口写成了 `async def`，但内部调用是同步的（torch 编码、ollama HTTP）。单进程单事件循环里，
这些调用会把循环整段卡住，并发度涨上去只是把请求堆在队列里。

| 接口 | 并发 | 吞吐 rps | P50 | P95 | P99 |
|---|---|---|---|---|---|
| search | 1 | 3.08 | 307 ms | 403 ms | 596 ms |
| search | 4 | 3.08 | 1280 ms | 1407 ms | 1636 ms |
| search | 8 | 3.11 | 2491 ms | 3555 ms | **4209 ms** |
| gateway | 1 | 20.3 | 48 ms | 59 ms | 66 ms |
| gateway | 8 | 21.2 | 367 ms | 385 ms | 424 ms |
| gateway | 16 | 20.9 | 583 ms | 1839 ms | **2292 ms** |

特征：**吞吐完全不随并发增长，P99 线性变差** —— 这就是串行化的指纹。

---

## 3. 修复：阻塞型路由改成同步 `def`，交给线程池

FastAPI 对 `def` 路由会在 anyio 线程池（默认 40 线程）里执行，事件循环不再被占住。
改动只有两个接口签名（`backend/api/search.py`、`backend/api/gateway.py`）。

| 接口 | 并发 | 吞吐 rps | P50 | P95 | P99 | 对比修复前 |
|---|---|---|---|---|---|---|
| search | 1 | 2.94 | 325 ms | 416 ms | 461 ms | 持平 |
| search | 4 | 3.94 | 1031 ms | 1244 ms | 1254 ms | 吞吐 +28% |
| search | 8 | 3.85 | 1779 ms | 2591 ms | **2630 ms** | P99 −37% |
| gateway | 1 | 18.6 | 52 ms | 69 ms | 83 ms | 持平 |
| gateway | 8 | 47.7 | 102 ms | 580 ms | 994 ms | **吞吐 +125%** |
| gateway | 16 | 52.5 | 94 ms | 806 ms | **833 ms** | **吞吐 +151%，P99 −64%** |

读法：
- **I/O 型（gateway）收益巨大**：线程池把「等后端」的时间重叠起来了，吞吐 20 → 52 rps。
- **CPU 型（search）收益有限**：torch 推理吃满 CPU，线程再多也只是抢核（还有 GIL）。
  吞吐从 3.1 到 3.9 rps 就到顶了，P99 仍会随并发上升。
  这是物理上限，不是代码写错了。
- 两条曲线说明：**「加线程」只解决等待，解决不了算力**。要再快得多进程（多 worker）
  或者换更小的模型 / 降精度。

## 4. 每千 token 成本

来自 `/metrics` 差值（`llm_tokens_total` 与 `llm_cost_usd_total`）：

| 指标 | 实测 |
|---|---|
| 压测期间网关调用 | 144 次 |
| 累计 token | 1296 |
| 累计成本 | $0.000000 |
| **每千 token 成本** | **$0.000000**（本地 Ollama 按 0 计价，只有电费与机器折旧） |
| **每千 token 的墙钟时间** | **3.475 秒** |

诚实说明：本地推理没有按量计费，所以「每千 token 成本」在本地恒为 0，这个数字本身没有商业意义。
它有意义的地方在于**口径已经打通**：价格表 `configs/model_prices.yaml` 一旦填上云厂商真实单价，
同一个指标直接给出美元金额。本地场景下更能说明成本的是「每千 token 的墙钟时间」。

不要把这个 0 写成「成本优化到 0」，那是误导。

## 5. 已知限制（面试要主动说）

1. **单进程单 worker**：没开 `--workers`，多核只用到一部分。再多进程要处理共享状态（FAISS 索引、SQLite 写锁）。
2. **压测不是真模型**：网关段用 FakeProvider + 固定延迟，测的是调度开销；真模型下瓶颈会移到推理本身。
3. **客户端与服务端同机**：会争抢 CPU，数字偏悲观。
4. **样本量小**：每级 24/48 个请求，P99 的统计意义有限（P99 只有约 1 个样本），趋势可用、绝对值别当 SLA。
