## Spacing Scale

All values achievable via inline CSS in `st.markdown()` or Streamlit's native padding system. Streamlit default spacing is ~10px internal. Overrides applied via `<style>` blocks in `app/main.py`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, citation markers |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, sidebar item spacing |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing, top padding |

Exceptions: none

**Source:** Streamlit CSS default overrides via `<style>`. Agent's discretion per CONTEXT.md.

All sizes achievable via Streamlit's default component hierarchy + optional CSS overrides in `app/main.py`.

| Body text | 16px | 400 (Regular) | 1.6 |
| Label / Meta | 14px | 400 (Regular) | 1.4 |

## Interaction Contracts

### 1. Document Upload Flow
```
User clicks "Upload Document" button
  → File picker opens (PDF only)
  → User selects file
  → Progress spinner appears
  → POST /api/v1/documents/upload called
  → Background task starts indexing
  → Status badge shows "Indexing..." (amber) 
  → Poll GET /api/v1/documents/{id}/status every 2s
  → On complete: badge turns "Ready" (green), document appears in list & sidebar selector
  → On error: red error banner with message
```

### 2. Chat Q&A Flow
```
User selects document from sidebar (if not already)
User types question in input
  → User message appears in chat as bubble
  → POST /api/v1/chat {question, document_id, history}
  → Response streams via Server-Sent Events or chunked response
  → st.write_stream renders tokens as they arrive
  → When complete: citations rendered as clickable [Article X, Section Y] markers
  → Below answer: collapsible "View Sources" expander shows retrieved chunks
  → Both Q&A pair saved to st.session_state.messages
```

### 3. Citation Interaction
```
Citation marker [Article X, Section Y] appears in answer text
  → User clicks the marker
  → Inline expansion shows source chunk text (preceding ~100 chars + chunk text)
  → Click again to collapse
  → Also available in "View Sources" section below
```

### 4. Multi-turn Chat
```
Each Q&A pair appended to st.session_state.messages
  → History sent with each /api/v1/chat request
  → LLM receives full conversation context
  → User sees full message history in scrollable area
  → "Clear conversation" option available (clears session state, no API call)
```

## Data Flow & API Contract Map

| Streamlit UI Action | API Endpoint | Response | UI Handling |
|-------------------|-------------|----------|-------------|
| Upload document | `POST /api/v1/documents/upload` | `{document_id, status: "processing"}` | Show spinner, start polling |
| Poll processing status | `GET /api/v1/documents/{id}/status` | `{status: "ready"/"processing"/"error"}` | Update badge, enable chat when ready |
| List documents | `GET /api/v1/documents` | `[{id, filename, status, chunk_count, created_at}]` | Populate sidebar selector + document cards |
| Get chunks for preview | `GET /api/v1/documents/{id}/chunks` | `[{article, section, subsection, text}]` | Render tree view |
| Ask question | `POST /api/v1/chat` | Streamed response with citations | `st.write_stream`, render citations |
| Health check | `GET /api/v1/health` | `{ollama, sqlite, faiss: "ok"/"error"}` | Show status in sidebar footer |

**Source:** CONTEXT.md D-01~D-08 (API structure), code_context section (integration points).
