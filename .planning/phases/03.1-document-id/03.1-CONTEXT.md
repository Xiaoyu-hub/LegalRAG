**Gathered:** 2026-05-15
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase fixes blockers and quality issues across the existing Phases 1-3 implementation. It does NOT introduce new features. Scope includes:

- Fix `requirements.txt` — add missing runtime dependencies (fastapi, uvicorn, requests, httpx, streamlit) and correct version for sentence-transformers
- Improve health check endpoint — non-blocking HTTP, BM25/Embedder state checks, FAISS validation
- Fix document_id handling — post-filter retrieval by document, eliminate raw SQLite queries from API layer, add `get_all_documents()` to MetadataStore
- Fix citation validation — English replacement text, article-only citation support, partial matching fallback

</domain>

<decisions>
## Implementation Decisions

### Dependencies
- **D-01:** Pin all runtime dependencies with exact versions — `fastapi`, `uvicorn[standard]`, `httpx`, `requests`, `streamlit` added to `requirements.txt` with verified versions
- **D-02:** `sentence-transformers` corrected to `3.2.1` (current stable); `5.4.1` is a non-existent version
- **D-03:** `streamlit` consolidated into `requirements.txt` — remove separate `RUN pip install streamlit` from Dockerfile frontend stage
- **D-04:** Keep single `requirements.txt` (no split files) — sufficient for MVP scale

### Health Check
- **D-05:** Replace synchronous `requests.get()` in health endpoint with `httpx.AsyncClient` — non-blocking Ollama check
- **D-06:** Add BM25 state check — verify `BM25Retriever.get_instance().corpus_size > 0`
- **D-07:** Add Embedder model check — verify model is loaded and responsive
- **D-08:** FAISS check enhanced — verify `VectorSearch.get_instance().size > 0` in addition to file existence
- **D-09:** Partial failure mode — per-service status reporting preserved; aggregate status reflects all checks

### Document ID Filtering
- **D-10:** Post-filter approach — after hybrid search retrieves top-K chunks, filter to only those matching the requested `document_id`
- **D-11:** Add `MetadataStore.get_all_documents()` method — eliminate raw SQLite queries from `documents.py`
- **D-12:** Refactor `_get_chunk_count_by_doc_id` to use `len(metadata_store.get_chunks_by_doc_id(doc_id))`
- **D-13:** If no chunks match the requested `document_id`, return empty results (graceful degradation)

### Citation Validation
- **D-14:** Change invalid citation replacement text from `[引用待核实]` to `[Citation needs verification]` — English consistency
- **D-15:** Support article-only citations (`[Article I]` without section number) — regex expanded to optionally match section
- **D-16:** Two-level validation: exact match (article + section pair) → partial match (citation text substring appears in any retrieved chunk's metadata)
- **D-17:** Keep existing regex `[Article X, Section Y]` as primary format; add fallback patterns

### Agent's Discretion
- Exact version numbers for dependency pinning (verified during planning/execution)
- Specific regex pattern for article-only citation matching
- Implementation details of post-filtering (where in the pipeline to inject document_id)
- Error handling specifics for each check component

</decisions>

<specifics>
## Specific Ideas

- `httpx.AsyncClient` preferred over `aiohttp` for async HTTP (lighter API, same maintainer as requests)
- BM25 corpus_size check is lightweight (in-memory attribute) — no performance concern
- Post-filtering for document_id can be done by adding `document_id` filter to `HybridSearch.retrieve()` or in the generation pipeline before chunk fetching

</specifics>
